## 2. Feasibility at ₹1–2L (SPEC §5 vs §6)

The SPEC's limits: directional ≤ 2–3% per trade (₹4–6k at ₹2L), defined-risk spreads ≤ 5% (₹10k at ₹2L, ₹5k at ₹1L), one lot per strategy.

| Strategy | Rough 1-lot risk (assumptions) | Fits? |
|---|---|---|
| Iron condor, 200-pt wings (§5.1) | (200 − credit) × 65 ≈ ₹9–12k | Borderline at ₹2L: fits 5% only if credit ≥ ~46 pts. ✗ at ₹1L → use 100-pt wings or require ₹2L |
| Directional ATM (§5.2) | Premium ~₹150 × 65 ≈ ₹10k; 10% stop ≈ ₹1k + ~₹60 costs | ✓ for 1 lot. ✗ the "scale in 2–4 tranches" rule breaks the 1-lot rule |
| ORB (§5.3) | 4-pt stop ≈ ₹260 + ~₹60 costs | ✓ size; ✗ statistics (see §3) |
| Calendar (§5.4) | Debit spread | ✓ (see the logic issue in §5) |
| Pre-earnings straddle (§5.5) | Stock F&O notional ≥ ₹5L (SEBI minimum); an ATM straddle before results at ~6–10% ≈ ₹30–60k premium, with no stop specified | ✗ |
| Swing: stock options (§5.8) | One ATM monthly at ~3% of ≥ ₹5L ≈ ₹15k+; "premium = max loss" | ✗ for most F&O stocks |
| Swing: bearish via stock futures (§5.8) | ≥ ₹5L notional × 5–7% stop ≈ ₹25–35k+, before gaps | ✗ |
| Trend sleeve, ETF (§5.6) | Cash ETF | ✓ |
| Event arb (Addendum) | Capped by the risk budget | ✓ (FIXED) |

**Proposed:**
- Make swing trading cash-only, plus index options.
- Defer §5.5 until capital is several times larger.
- Fix the internal inconsistency in §5.8: it sizes options with "premium = max loss" but also uses a 20–25% premium stop. Pick one, and remember gaps jump stops.

## 3. Statistical validity

1. **Power before research.** A strategy needs roughly `n ≈ (t·σ/μ)²` trades to reach t-stat t.
   - ORB example (assumed: win +8 / loss −4 pts, 40% win rate): μ = 0.8 pts, σ ≈ 5.9 pts.
   - That needs **≈ 490 trades for t = 3**, i.e. 1–2 years at 1–2 trades a day.
   - Costs are ~₹62 per round trip, ≈ 1 pt on a ₹100 premium (brokerage ₹40, STT on the sell premium, exchange charges, GST), so that example is **negative after costs** before any slippage.
   - *Proposed:* every research note starts with this calculation using its own assumed numbers.
2. **Deflated Sharpe needs a trial registry.** "Count every variant" only works if the backtester appends every run (parameters, sample, Sharpe) to a log automatically. *Proposed:* an M6 requirement.
3. **Monte Carlo by shuffling trades assumes iid trades.** That understates drawdowns for short-vol strategies, whose losses cluster. *Proposed:* block bootstrap by week or month.
4. **The paper gate (≥ 20 sessions) says little about negative-skew strategies.** Condors usually look fine for 20 sessions. *Proposed:* promotion also requires the stress-test loss to fit the limits, plus kill rules derived from the modelled loss distribution.
5. **Reference logs carry selection bias.** They are shared winners over 10–63 days, and PF 2.37 on 23 trades has a very wide confidence interval. "Funded trader" accounts are often prop *simulations* with idealised fills. *Proposed:* use only trades flagged LIVE; treat them as hypotheses, never as calibration.
6. **"Live ≈ ½ backtest" is a heuristic.** McLean–Pontiff measures post-publication decay. *Proposed:* measure our own paper-vs-backtest gap in M6.

## 5. SPEC, section by section

**§1 Modes**
- Automated TOTP login means the 2FA secret sits in `.env`. That is fine for Mode A data, but for Mode B check whether the broker or SEBI accept machine-generated TOTP as "daily 2FA".
- Shoonya is named as a fallback, but there is no `shoonya.py` in §2's layout.

**§2 Layout**
- `ops/scheduler` assumes systemd/cron; the PC runs Windows. (FIXED for event-arb with a Task Scheduler script.)
- Missing modules: capital allocator, tax-head tagging in the journal, instrument-master refresh job, trial registry.

**§3 Data**
1. **1-minute snapshots cannot simulate intraday stops.** A 10% premium stop (§5.2) can trigger and recover within a minute. *Proposed:* record every message all day for ATM ± 5 strikes of the current weekly; keep 1-minute snapshots for the rest of the band.
2. **IV-percentile filters (§5.1, §5.8) need a year of IV history** that the recorder won't have. *Proposed:* back-fill EOD ATM IV from F&O bhavcopy (free, years deep), and use India VIX percentile as the v1 filter.
3. **Point-in-time needs two timestamps per record:** *valid-for* and *known-at* (published or ingested). Examples: participant OI publishes after the close; bhavcopy files get corrected. *Proposed:* bitemporal columns from M2.
4. **Settlement-only holidays** (e.g. 19 Feb, 19 Mar, 1 Apr, 26 Aug 2026 per broker calendars) shift T+1 pay-outs. Also, the Muhurat-trade settlement date is not modelled. *Proposed:* a `settlement` segment in `holidays.csv` (M3).
5. The holidays table currently comes from the **CM** circular only. The F&O segment circular has not been read.
6. **Local SPAN calculation is large and error-prone.** *Proposed:* in v1, use the broker margin API with a simple worst-case scenario margin; full SPAN later.
7. **Order-flow and trade-sign metrics** (OFI, Lee–Ready) assume every quote change. Retail feeds are conflated snapshots, so label these approximations.

**§4 Analytics**
1. **One `T` is used for two jobs.** The forward/discount term `e^(rT)` should use *calendar* time (interest accrues daily), while volatility uses *variance/trading* time. *Proposed:* `T_cal` and `T_var` in `iv.py`, with a test.
2. **Near expiry**, put a floor on T and do not compute IV in the last ~30 minutes, where it is numerically meaningless.
3. **Implied correlation needs IVs for all members**, but the SPEC records only the top 10. State how the remaining weight is proxied.
4. **GEX/dealer gamma per strike** cannot be derived from participant OI (EOD, not per strike). Treat it as a research curiosity, never a gate.

**§5 Strategies**
- **§5.1:**
  - "Stops create the edge" is a fallacy (top priority #6).
  - The reference numbers (60-pt credit on a 200-wide condor) imply 25–30-delta shorts, contradicting the stated 15–20 delta.
  - It needs IV history (§3.2).
- **§5.2:** Scaling into 2–4 tranches conflicts with the 1-lot rule. The replicated strategy is therefore *different* from the reference trader's, so test whether the edge survives at 1 lot.
- **§5.3:** Statistics and costs (§3.1). Opening-minute spreads can be several points.
- **§5.4: logic error.** "Sell expensive weekly IV, buy cheaper monthly when the term structure is *steep*." With a steep (upward) curve the weekly is the *cheaper* one. Selling the weekly is attractive when the curve is *inverted*. Compare *forward* vol, not raw IVs; weekly IV includes event variance.
- **§5.5, §5.8:** see §2.
- **§5.6:** not a crash hedge (top priority #7).
- **§5.7:** collapses to on/off under the 1-lot cap.
- **§5.10:** numbering (5.10 comes before 5.9). OI updates arrive in batches, so "negative ΔOI" lags.

**§6 Risk**
- Missing: a **margin-headroom limit**. Intraday exchange margin hikes (VIX spikes) and peak-margin penalties can force square-offs. *Proposed:* keep utilisation ≤ ~50% of capital.
- Missing: **portfolio Greek caps** across strategies.
- Missing: an aggregate **sleeve allocation**.
- The 200-pt condor breaks the 5% cap at ₹1L.

**§7 Execution**
- PaperBroker needs a **passive-fill rule**: a resting limit fills only when the market trades through it, not when it merely touches.
- Specify an **entry pricing policy** (start at mid, step toward the touch N times, then abort), and add `PENDING_MODIFY` / `PENDING_CANCEL` states to the order FSM.
- Partial hedge fills (CLAUDE.md row above).
- Any manual UI that can reach a live broker must bind to localhost and require authentication.

**§8 Backtesting**
- Fidelity tiers:
  - **A** = recorded depth.
  - **B** = bhavcopy close ± a spread model calibrated on our recordings.
  - **C** = scenario-only.

  Every report states its tier. All stress windows before the recorder starts are tier B/C.
- Add the trial registry, block bootstrap and power analysis (§3).

**§9 Trade mining**
- Use LIVE-flagged trades only (§3.5).
- Anything parsed from the logs, CSVs included, is written only under `data/private/`.

**§10 Sidecars:** buyback bullet superseded (FIXED). For the yield stack: pledge/unpledge charges per request, and whether a pledged liquid ETF counts as a "cash-equivalent", must be verified before relying on it.

**§11 Costs:** add the IPFT levy (inferred, UNVERIFIED), DP charges (added for delivery), pledge charges and interest on margin shortfall. **Tax heads**: F&O = non-speculative business; intraday equity = *speculative* business; delivery and buybacks = capital gains. The journal must tag each trade.

**§12 Compliance:** the NSE announcements **RSS** is an official feed, so using it fits the data rules. The NSE website's JSON API is not used.

**§13 Milestones:** proposed order: **M2 → M1 (in parallel) → M3 → M4 → M5 → M8 (limits + kill switch) → M6 → M7 …**

## 7. Operations and security

- **Always-on host.** Laptop sleep and Windows Update will cut the recorder. A small Mumbai VPS with a static IP fixes recorder uptime *and* Mode B's static-IP rule (price to be verified).
- **Clock.** Configure `w32tm` NTP sync; the clock-skew QC depends on it.
- **Backups.** Recordings are irreplaceable. Keep a nightly copy of `data/parquet` to a second disk or cloud.
- **Secrets.** Prefer Windows Credential Manager (`keyring`) over a plaintext `.env` for TOTP and API secrets, and turn on BitLocker.
- **Edit rule tables carefully.** Excel can reformat dates; the loader rejects those loudly. Prefer a text editor.
- **CI** is not running yet (there is no GitHub repo).
