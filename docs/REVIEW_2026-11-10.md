## Bottom line

**The code is real scaffolding, but nothing past M0 meets its acceptance criteria.** It is mostly formulas and plumbing with one test per area. "BUILT" in `CONTEXT.md` means *the code exists*. Most criteria need things that don't exist yet: recordings, the reference logs, contract notes, paper sessions, a static IP.

**Several CLAUDE.md rules were broken.** The clear cases are fixed below, each with a test. The rest need your decision (§3).

**Some outputs were made from invented numbers.** The `shadow-scan`, `report`, `backtest` and `paper` commands, and `self-review` when run without a file, printed results built from hard-coded example inputs. Those included a deflated Sharpe, a "passes 2× slippage" verdict and a dashboard labelled as an Upstox feed. They now refuse to run unless you pass `DEMO=1`, and then say so.

## 3. Open findings (need your decision or more work)

1. **New sizing and risk parameters you never approved:**
   - the Kelly overlay (`kelly_max_risk_pct` 1.5, floor 0.25);
   - 50% margin headroom;
   - a 0.5× size cut after 3 consecutive losses, which means no trade at one lot;
   - a halt after 4 losses.

   Changing risk limits needs your OK (CLAUDE.md). They are more conservative than SPEC, apart from Kelly's old 5-lot cap, which is now fixed.
2. **Futures in V2.** Long index futures are undefined risk and about 8× leverage on ₹2L. The margin rule now blocks them. Decide whether futures are ever in scope.
3. **Untested numbers in the scoring.**
   - Scanner thresholds: confidence 75/80, RER 0.70/0.75, air-pocket 0.55, OBI 0.5, CVD z-score 2.
   - The "100-point score" weights.

   None of these are fitted or validated. Each variant counts as a trial for the deflated Sharpe, and every signal is unproven until t ≈ 3 out of sample.
4. **The scanner's "6 order-flow mechanics"** come from the PDF in the repo root. Its source and reliability are unknown, and the file sits outside `data/private/`, so a `git add .` would commit it.
5. **IV timing** (`analytics/iv.py`):
   - session length (385 min) and `risk_free_rate=0.068` are hard-coded defaults;
   - minutes left today are taken from `delta_s % 86400`, which is wrong;
   - the default path ignores holidays.

   Use `market_sessions.csv`, the trading calendar and a rate series instead.
6. **`fno_charges` uses UNVERIFIED rows by default** (`allow_unverified=True`; the IPFT levy rows are unverified). Costs list the unverified tables but don't block. This should be tightened once contract notes confirm the IPFT levy.
7. **Smaller gaps:**
   - `OPSRateLimiter` hard-codes the SEBI threshold of 10; it should read `sebi_algo_rules.csv`.
   - PaperBroker has no expiry or exercise settlement and no resting orders.
   - The kill-switch plan sends protected-market orders without reference prices.
   - Flattening on a feed disconnect is still unworkable (REVIEW_2026-11-09 §0).
8. **Tests.** Most areas have one happy-path test. Several "pass" checks run on hand-made trade lists, so they test the arithmetic, not any strategy. Nine regression tests were added here.
9. **Formatting.** Four files from that build fail `ruff format --check`. CI runs `ruff check` only.
10. **A demo report sits among real ones.** `reports/shadow_scanner/2026-11-10.html` was produced from invented inputs. I haven't deleted it; your call.
